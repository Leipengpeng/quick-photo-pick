# Quick Photo Pick 技术原理

Quick Photo Pick 把选片拆成两个层次。**连拍组**回答哪些照片适合直接比较，**场景组**把不同拍摄批次的相似取景放在一起浏览。每次连拍独立排序，从而可以在同一场景下保留不同批次中各自值得交付的照片。

## 1. 读取原片并确定连拍边界

程序先读取 EXIF 中的拍摄时间、亚秒、相机、镜头和焦距。原生连拍 ID 优先帮助划分批次。没有拍摄时间和原生连拍 ID 的图按单张处理。拍摄信息相符的同名 RAW 与 JPG 合成一个拍摄项，优先分析 RAW。RAW 经过 LibRaw 以相机白平衡渲染，分析阶段可复用同一次解码得到的 640 像素分组预览与 960 像素评分预览。

在时间线上先用拍摄间隔、相机和镜头信息约束候选，再用 64 位感知哈希快速比较画面。需要进一步判断时，用 SIFT 描述子做双向匹配，再通过 RANSAC 验证匹配点是否集中支持同一个几何变换。相邻帧的视觉证据和局部拍摄节奏共同进入动态规划，输出时间连续的分组。带明确序列标记的包围曝光、全景和焦点堆栈保留整组。

## 2. 在同一个连拍组内评分

人像分析使用 Facet 的 YuNet 人脸检测与 MediaPipe 面部关键点。闭眼判断可以结合单张的眼部状态和同一组内的人眼开度变化。眼部细节取眼周小块的拉普拉斯响应。满足条件的单人连拍以眼睛开得较大的照片为参照，对轻微变化更敏感。

人像排序先区分睁眼、待核实眼睛状态、闭眼，再在各自的分数区间比较整图细节、眼部细节和亮暗剪切。通用组以整图细节为主，辅以曝光剪切及边缘方向性。整图细节来自 Sobel 梯度能量，方向性只是一项弱信号。各项分数相对本组中位数归一化，缺少的观测量从本张照片的加权计算中剔除。组内分数表示同一组里的技术偏好。

报告可以展示构图、白平衡、表情等辅助观测，排序以代码中实际启用的技术信号为准。JPEG、PNG 及 RAW 渲染预览上的曝光剪切可以帮助找出同组异常亮暗。局部锐度回答眼周细节是否较清楚。大模型不参与默认流程的组内打分。

## 3. 跨拍摄批次聚合近似场景

每组先取开头和中间的代表图。初次匹配存在一定证据时可再看更清晰的代表图，或经 CLAHE 局部对比度归一化后复查。通过匹配至少需要 16 个几何内点，内点比例至少 55%，匹配点在两图上的覆盖分别至少为 10%，对齐后的双向画面重叠分别至少为 55%。

场景簇内的每对连拍组都要有直接验证的匹配，避免中间一组把两端不同取景串在一起。组数较多时，先用感知哈希分段和近似局部描述子检索候选，再做几何核验。

## 4. 输出和复核

程序把分组、场景、推荐照片和复核原因写进同一份审片数据。浏览器可直接打开随运行结果生成的 HTML。照片副本按原格式整理，输出以 SHA-256 核对内容一致。全景、包围曝光等组合序列的保护和普通连拍的优选名额分别处理。
